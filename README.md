# Kun — персональная панель дня (веб-версия)

«Kun» — по-узбекски «день». Одна страница, на которой собраны: погода и приветствие, задачи, список покупок, кошелёк и аналитика расходов, долги («Я должен» / «Мне должны»), статистика Xiaomi YU7 Max и здоровье. Веб-версия — «сестра» iOS-приложения: та же палитра, те же разделы и формулировки, тот же формат JSON для обмена данными.

* **`index.html`** — всё приложение в одном файле (HTML + CSS + JS-модуль + SVG-иконки + чертёж YU7), ≈ 560 КБ. Внешне подгружается только шрифт Inter (Google Fonts, с кириллицей). Библиотек нет: рендер, графики, «стекло», сцены погоды и анимации написаны на чистом JS/SVG/CSS/Canvas.
* **`screenshots/`** — снимки всех разделов в 1440×900 (`desktop-*`), 1024×768 (`tablet-*`) и 390×844 (`mobile-*`), плюс `anim-*.png` — раскадровки ключевых анимаций.

## Как это устроено

* **Маршруты** — только `location.hash`: `#home #tasks #shopping #finance #debts #car #health #settings`. Читаются при загрузке и на `hashchange`, поэтому работают и в песочнице артефакта.
* **Рендер** — каждый раздел описан функцией, возвращающей HTML-строку; маленький «морфер» применяет изменения к живому DOM по ключам `data-key`. Благодаря этому сохраняются фокус и прокрутка, а изменения анимируются: FLIP-перемещения в списках, плавный рост столбиков, «докручивание» чисел, зажигание делений шкалы.
* **Данные** меняются только через `commit(keys, fn)` → пересчёт → перерисовка → сохранение изменённых ключей. Все экраны связаны: расход сразу меняет баланс счёта, итоги месяца и карточку на главной; выполненная задача — счётчик на главной; платёж по долгу — остаток и баланс привязанного счёта; новый заряд — оба запаса хода везде.
* **Диалоги** — только внутристраничные: нижние листы (мобильный) / центрированные окна (десктоп) с пружинной анимацией и размытием фона; подтверждения, тосты «Отменить», меню «⋯». `alert/confirm/prompt`, `window.open`, `print` не используются.
* **Дизайн (v3 · Liquid Glass, эпоха iOS 27)** — живой тёмный фон: на почти чёрном #06070A медленно дрейфуют 4 больших цветовых поля (лайм, бирюза, фиолет, янтарь, циклы 38–60 с) + едва заметное зерно; палитра полей подстраивается под погоду и время суток (ясно днём — лайм+янтарь, облачно — бирюза+графит, дождь/снег — бирюза+синий, ночь — фиолет+глубокий синий). **Стекло — только навигационный слой**: плавающая боковая панель (отступ 14 px, радиус 28, активный пункт — стеклянная «линза», которая при переходе тянется к цели и упруго оседает), плавающая верхняя панель, на телефоне — плавающая капсула таб-бара, «аксессуар» авто над ним, листы, меню, тосты, кнопки и сегменты. Рецепт: `backdrop-filter: blur + saturate`, бликовая кромка и внутренний верхний блик, мягкая тень; в Chromium поверх — SVG-преломление (`feTurbulence` + `feDisplacementMap`) и более сильное преломление по краю (кольцо-маска), за `@supports` и только на трёх поверхностях над контентом (верхняя панель, таб-бар, аксессуар). Виджеты — «дымчатые» тонированные панели с кромкой света (радиус 28), таблицы и списки — сплошные (стекло никогда не лежит на длинных списках). Настройка **«Стекло»** (Прозрачное ↔ Тонированное, как в iOS 27) меняет CSS-переменные заливки/тонировки/размытия; крайнее правое положение и системное «Понижение прозрачности» (`prefers-reduced-transparency`) дают сплошные поверхности. Акцент — лайм #DEFF1C, шрифт — только Inter 400/500/600, табличные цифры.
* **Банковские карты — точные пропорции ISO/IEC 7810 ID-1**: `aspect-ratio: 85.6 / 53.98` (1,5858), скругление `3.71% / 5.89%` (3,18 мм), размер задаётся шириной. EMV-чип 14 % × 16,7 % в 11,7 % слева и 35 % сверху, знак бесконтактной оплаты, название счёта, крупный баланс, маска «•••• 06D9» (последние 4 символа id счёта — никаких выдуманных номеров), валюта; без логотипов. Основной счёт — олива→чёрный, остальные — графит, глубокая бирюза, фиолет, титан. Стопка как в Apple Wallet: карты перекрываются на 18 % высоты, основная — спереди; нажатие — карта поднимается, остальные собираются стопкой внизу; повторное нажатие — 3D-переворот на оборот (магнитная полоса, тип, валюта, начальный остаток, доход/расход за месяц, «Изменить»); блик и голографический отлив следуют за курсором.
* **Интерактивные виджеты**: погода — анимированная сцена за цифрами (солнце с лучами, облака, дождь, снег, туман, звёзды и луна, вспышки грозы; Canvas по коду WMO и `is_day`), почасовая кривая температуры с заливкой и столбиками осадков, стеклянный «ползунок» можно тянуть по часам — крупное табло (час, температура, ощущается, осадки, значок) обновляется «катящимися» цифрами, при отпускании пружиной возвращается к «Сейчас»; прогноз на 3 дня — стеклянные чипы с полосой мин–макс. Авто — наклон чертежа за курсором/пальцем (±6°, пружинный возврат), пульсирующее лаймовое свечение под колёсами, «жидкая» шкала заряда (волна мениска, блик, лайм → янтарь → коралл ниже 20 %); нажатие на шкалу — стеклянный лист с перетаскиваемым уровнем и живым пересчётом запаса; в «Зарядке» — частицы энергии, втекающие в шкалу. Финансы — стопка карт, кольцевая диаграмма с выбором сегмента (сегмент выдвигается, в центре — категория и сумма, легенда синхронизирована, наведение — предпросмотр), столбики со «скрабом» (стеклянный пузырь привязывается к столбцу), спарклайны в KPI. Задачи — «жидкое» кольцо прогресса, отметка каплей с галочкой и всплеском, переезд в «Выполнено», после последней задачи дня — один лаймовый салют. Здоровье — кольца как в «Активности» (Шаги / Сон / Вода) с градиентом и светящимися концами, нажатие подсвечивает кольцо и показывает метрику в центре. Долги — «жидкие» пилюли возврата и чип обратного отсчёта до срока.
* **Анимации** — пружинные кривые (свой мини-решатель пружины → CSS `linear()`; запасной вариант `cubic-bezier`). Запуск: поля фона проявляются и начинают дрейф, виджеты каскадом (50 мс) с пружиной, размытием 8 px → 0 и масштабом .96 → 1. Навигация: «линза» с эластичной деформацией, смена раздела — затухание + сдвиг 10 px по направлению движения; «Финансы ↔ Долги» — один экран, едет только линза сегмента. Числа: «катящиеся» цифры (одометр) и счёт; графики прорисовываются, «Линии / Столбцы» перетекают; карты — веер, подъём, 3D-переворот, блик; листы на десктопе вырастают из нажатой кнопки (FLIP), на телефоне выезжают снизу и закрываются свайпом; тосты — стеклянная пилюля с отскоком; на телефоне — «потянуть, чтобы обновить» (капля тянется и лопается в спиннер, обновляется погода); тактильный отклик (`navigator.vibrate`, только в жесте и на сенсорных экранах). Анимируются только `transform/opacity/filter`. При `prefers-reduced-motion` — только короткие затухания: фон статичен, нет параллакса, частиц, волн и сцены погоды (рисуется один кадр). Фон, волны и сцены ставятся на паузу, когда вкладка скрыта; Canvas-сцены — когда вне экрана.

## Два режима хостинга

### (a) Артефакт claude.ai (песочница, строгий CSP)

* `window.claude` есть только в этом режиме. Приложение сначала рисует оболочку («Подключаемся к хранилищу…»), затем ждёт `await window.claude.use("db")` и `await window.claude.use("user")` (оба могут вернуть `null` до ~10 с).
* Личные данные: `db.collection("data/users/" + await user.id())`, **один документ на каждый ключ формата**: `settings, accounts, categories, transactions, debts, tasks, shopping, carLogs, health`. Формат документа: `{ items: [...], updatedAt }`, для настроек — `{ value: {...}, updatedAt }`.
* Загрузка всех документов с таймаутом 10 с; результат `get()` разбирается защитно (`snap.data()`, `snap.data`, просто объект, `exists === false`). Ошибка чтения документа **не считается пустым документом** (иначе следующая запись затёрла бы данные): одна повторная попытка, затем переход на локальное хранилище с пояснением в баннере.
* Запись: только изменённые ключи, дебаунс ~600 мс, общая очередь (одна запись за раз), повтор с нарастающей паузой при ошибке, сброс очереди при `pagehide`. Пустая база → экран приветствия. «Сбросить всё» удаляет документы (`.delete()`).
* Если `db`/`user` = `null` → `localStorage`; если и он бросает исключение → данные только в памяти + ненавязчивый баннер «Данные не сохраняются в этом режиме».
* Запросы к другим хостам заблокированы, поэтому погода показывает честное состояние «Не удалось загрузить погоду · Нет доступа к сервису погоды» + «Повторить» (или кэш с бейджем «нет сети»), курс ЦБ — сообщение и ручной ввод, поиск города — ручные координаты. Числа никогда не выдумываются.

### (b) Обычный статический сайт (Render, GitHub Pages, открыть с диска)

* Нет `window.claude` → данные в `localStorage` (ключ `kun.v1`), кэш погоды — `kun.weather.v1`.
* Живая погода Open-Meteo (с кэшем и обновлением раз в 15 минут), поиск города через геокодинг Open-Meteo, курс ЦБ Узбекистана (`cbu.uz`, поля `Ccy`, `Rate`) — автоматически раз в день и кнопкой «Курс ЦБ».
* **Render**: New → Static Site → корень публикации — папка с `index.html` (команда сборки не нужна).
* **GitHub Pages**: положить `index.html` в корень репозитория (или `/docs`) и включить Pages.
* **С диска**: просто открыть `index.html` в браузере.

Навигация: десктоп (≥ 1100 px) — плавающая стеклянная боковая панель с группами «Меню / Жизнь / Инструменты», поиском по задачам, покупкам, операциям и долгам и мини-карточкой YU7 (сворачивается в рейку иконок, состояние запоминается) + плавающая стеклянная верхняя панель с заголовком, поиском, «+» и аватаром; 760–1099 px — рейка иконок; < 760 px — плавающий стеклянный таб-бар как в iOS 27: капсула в 21 px от краёв (+ safe-area), 5 вкладок «Главная, Задачи, Покупки, Финансы, Здоровье» и встроенный пункт поиска (открывает стеклянный лист поиска); активная вкладка — в «линзе», которая упруго перетекает и увеличивает значок, нажатие — пружинное сжатие с бликом, линзу можно тянуть пальцем по вкладкам; бар не сворачивается при прокрутке. Над ним — капсула-аксессуар авто (чертёж, «72 % · ≈ 365 км», мини-шкала) → «Авто». **Долги** теперь — сегмент «Финансов» («Обзор / Операции / Счета / Долги»); маршрут `#debts` по-прежнему работает и открывает «Финансы › Долги»; виджет долгов на главной остаётся. «Настройки» — через аватар. Кнопка «+» — быстрый ввод: задача, покупка, операция, заряд, здоровье, долг.

## Формат данных (JSON, версия 1)

Экспорт (Настройки → «Экспорт данных (JSON)») показывает JSON в поле с кнопкой «Скопировать» (буфер обмена; если браузер запретил — текст выделяется для Ctrl/⌘+C) и ссылкой «Скачать файл» (в песочнице может не работать). Импорт — файл или вставка текста → проверка `app === "kun"` и `version === 1` → подтверждение на странице → замена данных.

```json
{
  "app": "kun", "version": 1, "exportedAt": "2026-11-06T10:00:00+05:00",
  "settings": { "userName": "Джамшид", "city": {"name": "Ташкент", "lat": 41.2995, "lon": 69.2401},
    "baseCurrency": "UZS", "rates": {"USD": 12100, "EUR": 13900, "updatedAt": "2026-11-06"},
    "car": {"model": "Xiaomi YU7 Max", "grossKWh": 101.7, "usableKWh": 99.0, "cltcRangeKm": 760, "consumptionKWhPer100": 19.5},
    "goals": {"steps": 10000, "sleepHours": 8, "waterMl": 2000} },
  "accounts": [], "categories": [], "transactions": [], "debts": [],
  "tasks": [], "shopping": [], "carLogs": [], "health": []
}
```

Поля элементов — строго по спецификации (см. SPEC §4). Особенности веб-версии:

* **Совместимость с iOS-экспортом**: числа принимаются как JSON-числа (и как числовые строки); даты ISO-8601 с долями секунды или без, с `Z`, со смещением (`+05:00`, `+0500`) или без него; даты-числа (секунды от 2001-01-01 — формат Swift по умолчанию, а также Unix-секунды/миллисекунды) переводятся в ISO; `health.date` с временем приводится к `YYYY-MM-DD`. Регистр UUID не важен (это просто строки). Значки категорий/счетов могут быть именами SF Symbols (`cart.fill`, `creditcard`, `fork.knife` …) — они сопоставляются с веб-иконками.
* **Неизвестные поля сохраняются** (на уровне `settings` и каждого элемента), поэтому экспорт → импорт → экспорт даёт идентичный JSON (кроме `exportedAt`).
* Единственное дополнительное поле веб-версии: `settings.taskLists` — пользовательские списки задач, в которых ещё нет задач (iOS может его игнорировать).
* Деньги: суммы — в валюте счёта; UZS — целые, USD/EUR — округление до центов; сложение идёт в «копейках», без накопления ошибки. Перевод `toAmount` — в валюте счёта зачисления.

### Расчёты (SPEC §4)

* Баланс = начальный остаток + доходы − расходы − переводы со счёта + (toAmount ?? amount) переводов на счёт + эффект долгов, привязанных к счёту (взял: +сумма − платежи; дал: −сумма + платежи; при другой валюте — по курсу).
* Переводы и долги не входят в доходы/расходы и аналитику. Итоги в сумах = значение × курс (UZS = 1); архивные счета не входят в общий баланс.
* Долг: остаток = сумма − Σплатежей; закрыт при остатке ≤ 0; просрочен, если срок прошёл и остаток > 0.
* Авто: текущий заряд — последняя по дате запись (показание или конечный % зарядки); пробег — последний известный; энергия = % × полезная ёмкость; реальный запас = энергия / расход × 100 (с округлением вниз: 72% → 71,3 кВт·ч → ≈ 365 км); CLTC = % × 760 (547 км); измеренный расход — по соседним показаниям без зарядки между ними, если ≥ 30 км; время зарядки — линейная оценка.
* «Сегодня» для задач = срок сегодня или просрочено и не выполнено.

## Проверено

Автотесты на Playwright + Google Chrome 153 (headless), сеть замокана (Open-Meteo, геокодинг, cbu.uz, Google Fonts — реальные файлы шрифтов), падение на любой ошибке консоли / необработанном исключении. Итог прогонов на финальной сборке дизайна v3 (6 ноября 2026): **133/133** проверок пользовательского сценария (`walkthrough.mjs`), **72/72** проверок режимов (`modes.mjs`), **56/56** проверок новых взаимодействий v3 (`v3.mjs`), `autorate.mjs` (3/3) и `negframe.mjs` (2/2) — всё зелёное; скриншоты 1440×900, 1024×768 и 390×844 (`screens.mjs`) и раскадровки анимаций (`anim.mjs`) без ошибок консоли. Скриншоты просмотрены глазами (глубина, читаемость поверх фона, выравнивание, длинные названия, 1 000 000 000 сум, ширина 360 px).

* **Пользовательский сценарий (localStorage, 1440×900)** — все функциональные проверки v2 сохранены: онбординг → демо-данные; погода; отметка задачи на главной → счётчик и подзаголовок; расход 125 000 → баланс Uzcard, расходы месяца и итог на главной меняются ровно на 125 000; перевод UZS → USD с автоматическим `toAmount` $100; платёж по долгу и «Погасить полностью»; просроченный долг; авто: ползунок 50% → 253 / 380 км вживую, перетаскивание шкалы, зарядка 50→80% с 29,7 кВт·ч и расходом −30 000, время зарядки; покупки (разбор «молоко 2 л», «Завершить покупку» → расход 85 000, «Очистить отмеченные»); задачи (разбор «завтра 18:30 !», редактор, удаление + «Отменить», фильтры и списки); здоровье и цели; финансы (поиск, фильтры, месяц, правка/удаление/отмена, сортировка, массовое удаление, счёт в EUR, архив, удаление, категории); настройки (имя, курс ЦБ и ручной, город → новая погода, расход авто); **экспорт → сброс → импорт → экспорт идентичен**; перезагрузка сохраняет данные и маршрут; импорт «iOS-подобного» JSON; 360 px — нет горизонтальной прокрутки и обрезанных чисел на всех разделах при 1 000 000 000 сум и длинных названиях. Обновлены только селекторы под новый макет (почасовая кривая вместо столбиков; карта счёта открывается через стопку: поднять → перевернуть → «Изменить»; в фильтре списков не учитываются уходящие строки).
* **Режимы хранения** (мок `window.claude`): оболочка → подключение; пустая база → онбординг; 9 документов в `data/users/<id>`; быстрые правки сливаются в одну запись; отметка задачи пишет только `tasks`; повторная сессия загружает данные; сброс удаляет все 9 документов; `use()` → `null` → `localStorage`; ошибка чтения → данные аккаунта не затираются; `localStorage` бросает исключение → режим памяти с баннером.

В headless-Chrome без GPU (программная композиция) главная держит ≈ 44 мс/кадр, без «стекла» — 17 мс; на устройствах с GPU это работа композитора.

## Не проверено

* **Реальный GPU и реальные телефоны**: тесты шли только в headless Chrome без GPU; плавность 60 fps на среднем телефоне не измерялась. Внешний вид SVG-преломления в настоящем Chrome с GPU не сравнивался с headless (в этой сборке Chrome фильтр `url()` работает только если стоит после `blur()` — так и сделано; Safari и Firefox получают только размытие + блики — визуально не проверялись).
* Safari / iOS Safari и Firefox вообще не запускались: `@property`, `color-mix()`, контейнерные единицы `cqw`, `:has()`, `linear()` — для старых версий есть запасные значения, но вид не сверялся. В Safari нет `navigator.vibrate` — тактильный отклик там просто отсутствует.
* Реальная песочница артефакта claude.ai и настоящий `window.claude` — только собственный мок API.
* Живые запросы к Open-Meteo (в т. ч. новое поле `hourly=apparent_temperature` для «ощущается» при скрабе — в моке его нет, поэтому в тестах при скрабе показывается только температура и осадки), геокодингу и cbu.uz в автотестах замоканы.
* Перетаскивание линзы таб-бара пальцем и наклон чертежа касанием проверены только мышью/кодом, не на сенсорном устройстве; «потянуть, чтобы обновить» — синтетическими CDP-касаниями.
* Импорт настоящего экспорта iOS-приложения — проверен синтетический JSON «в стиле iOS».
* Буфер обмена и скачивание Blob внутри песочницы артефакта (предусмотрены запасные пути).
