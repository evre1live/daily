# Kun — персональная панель дня (веб-версия)

«Kun» — по-узбекски «день». Одна страница, на которой собраны: погода и приветствие, задачи, список покупок, кошелёк и аналитика расходов, долги («Я должен» / «Мне должны»), статистика Xiaomi YU7 Max и здоровье. Веб-версия — «сестра» iOS-приложения: та же палитра, те же разделы и формулировки, тот же формат JSON для обмена данными.

* **`index.html`** — всё приложение в одном файле (HTML + CSS + JS-модуль + SVG-иконки), ≈ 350 КБ. Внешне подгружаются только шрифты Google Fonts (Cormorant Garamond и Manrope с кириллицей). Библиотек нет: рендер, графики и анимации написаны на чистом JS/SVG/CSS.
* **`screenshots/`** — снимки всех разделов в 1440×900 (`desktop-*`) и 390×844 (`mobile-*`).

## Как это устроено

* **Маршруты** — только `location.hash`: `#home #tasks #shopping #finance #debts #car #health #settings`. Читаются при загрузке и на `hashchange`, поэтому работают и в песочнице артефакта.
* **Рендер** — каждый раздел описан функцией, возвращающей HTML-строку; маленький «морфер» применяет изменения к живому DOM по ключам `data-key`. Благодаря этому сохраняются фокус и прокрутка, а изменения анимируются: FLIP-перемещения в списках, плавный рост столбиков, «докручивание» чисел, зажигание делений шкалы.
* **Данные** меняются только через `commit(keys, fn)` → пересчёт → перерисовка → сохранение изменённых ключей. Все экраны связаны: расход сразу меняет баланс счёта, итоги месяца и карточку на главной; выполненная задача — счётчик на главной; платёж по долгу — остаток и баланс привязанного счёта; новый заряд — оба запаса хода везде.
* **Диалоги** — только внутристраничные: нижние листы (мобильный) / центрированные окна (десктоп) с пружинной анимацией и размытием фона; подтверждения, тосты «Отменить», меню «⋯». `alert/confirm/prompt`, `window.open`, `print` не используются.
* **Дизайн** — тёмный тёплый уголь, медное свечение, тонкая антиква в заголовках, «таблеточная» навигация со скользящим индикатором, тонкие столбики, дуга из делений (батарея), кольцо с орбитой (шаги), ступенчатый график с медной «таблеткой» (почасовая погода), зеркальные столбики (доходы/расходы), медная подсветка рамки.
* **Анимации** — пружинные кривые (свой мини-решатель пружины → CSS `linear()`; запасной вариант `cubic-bezier(.22,1,.36,1)`), появление карточек каскадом с размытием → резкость, счёт чисел, зажигание делений по одному, рост столбиков, прорисовка колец, скольжение таблетки «сейчас», переходы между разделами со сдвигом в сторону движения, FLIP для списков, анимированная галочка и зачёркивание, подсветка карточки за курсором, нажатие с уменьшением, медленно дрейфующие фоновые свечения. Анимируются только `transform/opacity/filter`. При `prefers-reduced-motion` остаются только короткие затухания.

## Два режима хостинга

### (a) Артефакт claude.ai (песочница, строгий CSP)

* `window.claude` есть только в этом режиме. Приложение сначала рисует оболочку («Подключаемся к хранилищу…»), затем ждёт `await window.claude.use("db")` и `await window.claude.use("user")` (оба могут вернуть `null` до ~10 с).
* Личные данные: `db.collection("data/users/" + await user.id())`, **один документ на каждый ключ формата**: `settings, accounts, categories, transactions, debts, tasks, shopping, carLogs, health`. Формат документа: `{ items: [...], updatedAt }`, для настроек — `{ value: {...}, updatedAt }`.
* Загрузка всех документов с таймаутом 10 с; результат `get()` разбирается защитно (`snap.data()`, `snap.data`, просто объект, `exists === false`). Ошибка чтения документа **не считается пустым документом** (иначе следующая запись затёрла бы данные): одна повторная попытка, затем переход на локальное хранилище с пояснением в баннере.
* Запись: только изменённые ключи, дебаунс ~600 мс, общая очередь (одна запись за раз), повтор с нарастающей паузой при ошибке, сброс очереди при `pagehide`. Пустая база → экран приветствия. «Сбросить всё» удаляет документы (`.delete()`).
* Если `db`/`user` = `null` → `localStorage`; если и он бросает исключение → данные только в памяти + ненавязчивый баннер «Данные не сохраняются в этом режиме».
* Запросы к другим хостам заблокированы, поэтому погода показывает честное состояние «Не удалось загрузить погоду · Нет доступа к сервису погоды» + «Повторить» (или кэш с бейджем «нет сети»), курс ЦБ — сообщение и ручной ввод, поиск города — ручные координаты. Числа никогда не выдумываются.

### (b) Обычный статический сайт (Render, GitHub Pages, открыть с диска)

* Нет `window.claude` → данные в `localStorage` (ключ `kun.v1`), кэш погоды — `kun.weather.v1`.
* Живая погода Open-Meteo (с кэшем и обновлением раз в 15 минут), поиск города через геокодинг Open-Meteo, курс ЦБ Узбекистана (`cbu.uz`, поля `Ccy`, `Rate`) — автоматически раз в день и кнопкой «Курс ЦБ».
* **Render**: New → Static Site → корень публикации — папка с `index.html` (команда сборки не нужна).
* **GitHub Pages**: положить `index.html` в корень репозитория (или `/docs`) и включить Pages.
* **С диска**: просто открыть `index.html` в браузере.

## Формат данных (JSON, версия 1)

Экспорт (Настройки → «Экспорт данных (JSON)») показывает JSON в поле с кнопкой «Скопировать» (буфер обмена; если браузер запретил — текст выделяется для Ctrl/⌘+C) и ссылкой «Скачать файл» (в песочнице может не работать). Импорт — файл или вставка текста → проверка `app === "kun"` и `version === 1` → подтверждение на странице → замена данных.

```json
{
  "app": "kun", "version": 1, "exportedAt": "2026-11-06T10:00:00+05:00",
  "settings": { "userName": "Джамшид", "city": {"name": "Ташкент", "lat": 41.2995, "lon": 69.2401},
    "baseCurrency": "UZS", "rates": {"USD": 12100, "EUR": 13900, "updatedAt": "2026-11-06"},
    "car": {"model": "Xiaomi YU7 Max", "grossKWh": 101.7, "usableKWh": 99.0, "cltcRangeKm": 760, "consumptionKWhPer100": 19.5},
    "goals": {"steps": 10000, "sleepHours": 8, "waterMl": 2000} },
  "accounts": [], "categories": [], "transactions": [], "debts": [],
  "tasks": [], "shopping": [], "carLogs": [], "health": []
}
```

Поля элементов — строго по спецификации (см. SPEC §4). Особенности веб-версии:

* **Совместимость с iOS-экспортом**: числа принимаются как JSON-числа (и как числовые строки); даты ISO-8601 с долями секунды или без, с `Z`, со смещением (`+05:00`, `+0500`) или без него; даты-числа (секунды от 2001-01-01 — формат Swift по умолчанию, а также Unix-секунды/миллисекунды) переводятся в ISO; `health.date` с временем приводится к `YYYY-MM-DD`. Регистр UUID не важен (это просто строки). Значки категорий/счетов могут быть именами SF Symbols (`cart.fill`, `creditcard`, `fork.knife` …) — они сопоставляются с веб-иконками.
* **Неизвестные поля сохраняются** (на уровне `settings` и каждого элемента), поэтому экспорт → импорт → экспорт даёт идентичный JSON (кроме `exportedAt`).
* Единственное дополнительное поле веб-версии: `settings.taskLists` — пользовательские списки задач, в которых ещё нет задач (iOS может его игнорировать).
* Деньги: суммы — в валюте счёта; UZS — целые, USD/EUR — округление до центов; сложение идёт в «копейках», без накопления ошибки. Перевод `toAmount` — в валюте счёта зачисления.

### Расчёты (SPEC §4)

* Баланс = начальный остаток + доходы − расходы − переводы со счёта + (toAmount ?? amount) переводов на счёт + эффект долгов, привязанных к счёту (взял: +сумма − платежи; дал: −сумма + платежи; при другой валюте — по курсу).
* Переводы и долги не входят в доходы/расходы и аналитику. Итоги в сумах = значение × курс (UZS = 1); архивные счета не входят в общий баланс.
* Долг: остаток = сумма − Σплатежей; закрыт при остатке ≤ 0; просрочен, если срок прошёл и остаток > 0.
* Авто: текущий заряд — последняя по дате запись (показание или конечный % зарядки); пробег — последний известный; энергия = % × полезная ёмкость; реальный запас = энергия / расход × 100 (с округлением вниз: 72% → 71,3 кВт·ч → ≈ 365 км); CLTC = % × 760 (547 км); измеренный расход — по соседним показаниям без зарядки между ними, если ≥ 30 км; время зарядки — линейная оценка.
* «Сегодня» для задач = срок сегодня или просрочено и не выполнено.

## Проверено

Автотесты на Playwright + Google Chrome 153 (headless), сеть замокана (Open-Meteo, геокодинг, cbu.uz, Google Fonts — реальные файлы шрифтов), падение на любой ошибке консоли / необработанном исключении. Итог последних прогонов на финальной сборке — **103/103** проверок пользовательского сценария и **55/55** проверок режимов (скрипты `walkthrough.mjs`, `modes.mjs`, `screens.mjs` в `/home/claude/kun-test`):

* **Пользовательский сценарий (localStorage, 1440×900)**: онбординг → демо-данные; погода, почасовой график, прогноз; отметка задачи на главной → счётчик «X из Y» и подзаголовок; расход 125 000 → баланс Uzcard, расходы месяца и итог на главной меняются ровно на 125 000; перевод UZS → USD с автоматическим `toAmount` $100, без влияния на расходы и общий итог; платёж по долгу (2 000 000 → 1 500 000, баланс привязанного счёта +500 000), «Погасить полностью» → «закрыт», на главной 0; новый долг с прошедшим сроком → «просрочен»; авто: ползунок 50% → 253 / 380 км вживую, перетаскивание дуги, сохранение → страница авто и главная; зарядка 50→80% с кВт·ч = 29,7 и расходом −30 000; время зарядки для 60 кВт; покупки: быстрый ввод с главной и раздела, разбор «молоко 2 л» / «яйца 10», переезд в «В корзине», «Завершить покупку» → расход 85 000 в «Продукты», «Очистить отмеченные»; задачи: разбор «завтра 18:30 !», редактор, удаление + «Отменить», фильтры и списки, новый список; здоровье: ввод, кольцо, главная, цели; финансы: поиск, фильтры, переключение месяца, редактирование/удаление/отмена операции, счёт в EUR (+1 390 000 в итог), архив, удаление, категории; настройки: имя, курс ЦБ (мок) и ручной курс, поиск города → новая погода, расход авто → пересчёт запаса; **экспорт → сброс → импорт → экспорт идентичен**; копирование в буфер; отказ импорта чужого файла; перезагрузка сохраняет данные и маршрут; импорт «iOS-подобного» JSON (UUID в верхнем регистре, даты с долями секунды/`Z`/без зоны, дробные суммы, лишние поля) с проверкой балансов и сохранением лишних полей; 360 px: нет горизонтальной прокрутки и обрезанных чисел на всех разделах при счёте 1 000 000 000 сум и длинных названиях.
* **Режимы хранения** (мок `window.claude`): сначала оболочка, затем подключение; пустая база → онбординг; 9 документов по ключам в `data/users/<id>` с формой `{items|value, updatedAt}`; ничего не пишется в `localStorage`; быстрые правки сливаются в одну запись; отметка задачи пишет только `tasks`; повторная сессия загружает данные из базы; сброс удаляет все 9 документов; разные формы ответа `get()`; `use()` → `null` → `localStorage`; ошибка чтения документа → данные аккаунта не затираются, баннер; `localStorage` бросает исключение → режим памяти с баннером «Данные не сохраняются в этом режиме», приложение полностью работает.
* **Сеть**: погода недоступна → «Не удалось загрузить погоду» без чисел, «Повторить» загружает; офлайн с кэшем → данные + бейдж «нет сети»; cbu.uz недоступен → сообщение; геокодинг недоступен → ручные координаты.
* **Мобильный (390×844, touch)**: нижняя панель, «Ещё» → разделы, индикатор вкладки, нижний лист и закрытие свайпом вниз, меню «⋯» у строк, отсутствие горизонтальной прокрутки.
* **Reduced motion**: класс `rm`, нет длинных трансформ-анимаций, отметка мгновенная.
* Скриншоты всех разделов (включая листы, онбординг и пустые состояния) просмотрены и сверены с референсом.

## Не проверено

* Реальная песочница артефакта claude.ai и настоящий `window.claude` — проверено только на собственном моке API; точная форма ответов `get()` неизвестна (код написан защитно).
* Реальные запросы к Open-Meteo, геокодингу и cbu.uz — в среде сборки интернет закрыт, использовались моки по документированным форматам. Отдаёт ли cbu.uz заголовки CORS — неизвестно; если нет, браузер заблокирует запрос и приложение молча останется на ручном курсе.
* Загрузка шрифтов с fonts.googleapis.com (в тестах те же файлы отдавались локально).
* Safari, Firefox, реальные iPhone/Android: тесты шли только в Chrome; для старых браузеров без CSS `linear()` используется запасная кривая. Плавность 60 fps на реальных устройствах не измерялась (headless без GPU).
* Импорт настоящего экспорта iOS-приложения — проверен синтетический JSON «в стиле iOS».
* Буфер обмена и скачивание Blob внутри песочницы артефакта (предусмотрены запасные пути).
